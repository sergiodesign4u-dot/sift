Variants and states

Twenty-four pixels, and that number is a named exception rather than an oversight: a 44px checkbox would double the height of every row in a ranked list, and the ranked list is the screen this product exists for. The only axis is the state of the box, unchecked or checked, so the columns are those two and the rows are the states checkbox.css paints: rest, hover, focus-visible, disabled. Checked is the real checked attribute. Active is not shown: the CSS has no pressed rule. Hover on a checked box shows no change, because the checked rule sets the same border colour and comes after it.

How to use it

When

Two places, and they are opposite in weight. On 2.0 it selects themes for a brief, where it is the quiet start of the product's main job and the reason the selection bar exists. On 7.2 it carries a compliance promise: PII scrubbing is on by default, and the checkbox is how the product SHOWS that rather than claiming it in a paragraph.

That second use is why the checked state takes the accent. A default that matters is worth seeing from across the screen.

When not

  • To offer one of several options: take a radio, which this product does not have. If it ever needs one, it is a new component with its own page, not a checkbox with a round corner.
  • To switch something on immediately: take a toggle, which this product does not have. A checkbox is part of a form and commits with the form. On 7.2 the settings are saved by a button, which is why a checkbox is right there.

To select a row in a list where 44px is available: the same checkbox. The exception is the row height, not the taste. Where the row can afford 44, use 44.
